01

BluetoothAdapter

El punto de entrada para todo lo relacionado con Bluetooth en Android es la clase BluetoothAdapter. A través de ella podemos verificar si el dispositivo tiene Bluetooth, activarlo, obtener los dispositivos vinculados y establecer nuevas conexiones.

🔗

🔍

⚡

val bluetoothAdapter = BluetoothAdapter.getDefaultAdapter()

Con el adaptador obtenido, podemos recuperar los dispositivos ya emparejados mediante bondedDevices, que devuelve un conjunto de objetos BluetoothDevice, cada uno con información como nombre y dirección MAC.

@SuppressLint("MissingPermission")
fun getBondedDevices(): Set<BluetoothDevice>? {
    return bluetoothAdapter?.bondedDevices
}
02

BluetoothSocket

Para establecer comunicación usamos un BluetoothSocket, que funciona como un canal bidireccional de datos. Primero definimos el UUID del servicio SPP (Serial Port Profile), un identificador estándar para conexiones serie:

val uuid = UUID.fromString("00001101-0000-1000-8000-00805F9B34FB")

Luego creamos el canal de comunicación hacia ese servicio:

socket = device.createRfcommSocketToServiceRecord(uuid)

Con el socket activo podemos:

  • Conectarnos al dispositivo remoto
  • Enviar datos con outputStream.write()
  • Recibir datos con inputStream.read()
  • Cerrar la conexión con close()
⚠️ La operación socket.connect() puede tardar varios segundos. Si se llama directamente en el hilo principal, la interfaz se congelará. Por eso la función de conexión debe marcarse como suspend y ejecutarse en Dispatchers.IO.
03

Sealed class de estados

Para representar los distintos resultados posibles de la conexión usamos una sealed class. Este tipo de clase permite definir un conjunto cerrado de subtipos, lo que facilita manejar cada caso con when de forma exhaustiva y segura.

Idle
Sin actividad. Estado inicial de la app.
Loading
Intentando conectar con el dispositivo.
Success
Conexión establecida. Devuelve el BluetoothDevice.
Error
Falló la conexión. Devuelve el mensaje de error.
sealed class BluetoothState<out T> {
    object Idle    : BluetoothState<Nothing>()
    object Loading : BluetoothState<Nothing>()
    data class Success<T>(val data: T)       : BluetoothState<T>()
    data class Error(val message: String)    : BluetoothState<Nothing>()
}
04

Método connect

La función de conexión es suspend para no bloquear el hilo principal. Mueve la operación bloqueante al dispatcher de IO con withContext(Dispatchers.IO). Al terminar, la ejecución regresa automáticamente al hilo original.

Usamos withTimeout para establecer un límite máximo de 10 segundos:

0s 10s │ │ ├──── esperando ───────┤ ← sin respuesta → lanza TimeoutCancellationException │ └── conecta antes de 10s → continúa normal
@SuppressLint("MissingPermission")
suspend fun connect(
    deviceName: String,
    bluetooth: (BluetoothState<BluetoothDevice>) -> Unit
) {
    bluetooth(BluetoothState.Loading)
    try {
        val bluetoothDevice =
            bluetoothAdapter?.bondedDevices?.firstOrNull {
                it.name == deviceName
            } ?: run {
                bluetooth(BluetoothState.Error("Dispositivo no encontrado"))
                return
            }

        val uuid = UUID.fromString("00001101-0000-1000-8000-00805F9B34FB")
        socket?.close()
        socket = bluetoothDevice.createRfcommSocketToServiceRecord(uuid)

        withContext(Dispatchers.IO) {
            withTimeout(10_000L) { socket?.connect() }
        }

        bluetooth(BluetoothState.Success(bluetoothDevice))

    } catch (e: TimeoutCancellationException) {
        socket = null
        bluetooth(BluetoothState.Error("Tiempo agotado. Verifica que el dispositivo esté encendido y cerca"))
    } catch (e: IOException) {
        socket = null
        val mensaje = when {
            e.message?.contains("Connection refused") == true -> "Dispositivo rechazó la conexión"
            e.message?.contains("Host is down")        == true -> "Dispositivo apagado o fuera de rango"
            e.message?.contains("read failed")         == true -> "El dispositivo no responde"
            else -> "Error de conexión: ${e.message}"
        }
        bluetooth(BluetoothState.Error(mensaje))
    } catch (e: SecurityException) {
        bluetooth(BluetoothState.Error("Permiso Bluetooth denegado"))
    }
}

05

Envío de datos

El módulo HC-06 trabaja a nivel de bytes. Para enviar datos usamos outputStream.write(), que recibe un ByteArray. Es importante concatenar un salto de línea \n al final de cada mensaje para que Arduino sepa dónde termina, y llamar a flush() para forzar el envío inmediato sin esperar a que se llene el buffer.

Kotlin Buffer HC-06 │ │ │ ├── write("1\n") ──► │ datos en memoria │ ├── flush() ───────► │ fuerza envío ───►│ │ │ inmediato │
fun sendData(data: String) {
    try {
        socket?.outputStream?.write((data + "\n").toByteArray())
        socket?.outputStream?.flush()
    } catch (e: Exception) {
        Log.e("Bluetooth", "Error al enviar datos", e)
        socket = null
    }
}
💡 Sin flush(), los datos quedan acumulados en memoria y pueden no llegar al módulo HC-06, especialmente con mensajes cortos como "1" o "0".
06

Permisos en Android 12 y superior

A partir de Android 12 (API 31), Google rediseñó el sistema de permisos de Bluetooth. Las apps deben solicitarlos en tiempo de ejecución, no solo declararlos en el manifiesto.

Android 11 o menorAndroid 12 o mayor
BLUETOOTHBLUETOOTH_CONNECT
BLUETOOTH_ADMINBLUETOOTH_SCAN
ACCESS_FINE_LOCATIONBLUETOOTH_ADVERTISE
 
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.S) {
    if (ActivityCompat.checkSelfPermission(
            this, Manifest.permission.BLUETOOTH_CONNECT
        ) != PackageManager.PERMISSION_GRANTED
    ) {
        ActivityCompat.requestPermissions(
            this,
            arrayOf(
                Manifest.permission.BLUETOOTH_CONNECT,
                Manifest.permission.BLUETOOTH_SCAN
            ),
            1
        )
    }
}
⚠️ checkSelfPermission devuelve 0 si el permiso está concedido (PERMISSION_GRANTED) y -1 si no lo está (PERMISSION_DENIED). La condición != PERMISSION_GRANTED solo entra al bloque cuando el usuario aún no ha otorgado el permiso.
07

Configuración en Arduino

En el lado del hardware usamos la librería SoftwareSerial.h para crear una comunicación serial en los pines 2 y 3, liberando los pines 0 y 1 para el Monitor Serie del IDE de Arduino. Esto nos permite ver los datos recibidos desde la app mientras el circuito funciona.

#include <SoftwareSerial.h>
//                  RX  TX
SoftwareSerial bt(2, 3);

void setup() {
    Serial.begin(9600);  // Monitor Serie (USB)
    bt.begin(9600);      // Módulo HC-06
    pinMode(7, OUTPUT);
}

void loop() {
    if (bt.available()) {
        char dato = bt.read();
        Serial.println(dato);

        if (dato == '1') digitalWrite(7, HIGH);
        if (dato == '0') digitalWrite(7, LOW);
    }
}

Conexión del módulo HC-06

El pin RX del HC-06 opera a 3.3V. Para protegerlo, usamos un divisor de voltaje entre el pin TX del Arduino (5V) y el pin RX del módulo:

Arduino TX ── 1kΩ ──┬── HC-06 RX │ 2kΩ │ GND
✅ La conexión debe ser cruzada: TX del Arduino con RX del HC-06, y RX del Arduino con TX del HC-06. Para ver los datos recibidos, abre el Monitor Serie con Ctrl + Shift + M y selecciona 9600 baud.
